1. Known Issues to Resolve
BUG-001 · NOTIFICATION CENTER
Notification center is non-functional — no live notifications delivered
The notification center on the Employee Portal is not working as expected. Employees do not receive real-time notifications for any portal events — such as evaluation submissions, status changes, or approvals.

» Expected
The notification center must deliver live, real-time notifications to the respective user whenever a relevant portal event occurs. Notifications should appear immediately without requiring a page refresh, and must cover all stages: form submission, forwarding between reviewers, and final approval.

BUG-002 · EVALUATION STATUS
"Last Updated" timestamp on evaluation status is inaccurate
The evaluation status panel displays a "Last Updated" date and time that does not reflect the actual timestamp of the most recent action taken on that evaluation record.

» Expected
The "Last Updated" timestamp must always reflect the exact date and time of the most recent change — whether a submission, a rating alteration, a forwarding step, or a final lock and approval by HR. The value must update dynamically and accurately at every stage of the workflow.

BUG-003 · DRAFT DUPLICATION
Employees can create multiple drafts on the same evaluation template
The system currently allows an employee to save more than one draft for the same evaluation template simultaneously. This creates duplicate, conflicting draft records and causes confusion about which version is the active one.

» Expected
An employee must only be allowed a single draft per evaluation template at any given time. If a draft already exists for a template, the system must prevent creation of a new, separate draft. Any attempt to start a new draft should instead automatically open and continue from the existing one.

BUG-004 · TEMPLATE VISIBILITY
A template with an existing draft still appears in "Available Templates"
When an employee has a saved draft for an evaluation template, that same template continues to appear in the "Available Templates" list as though no work has been started — causing the employee to accidentally initiate a brand-new form instead of resuming their draft.

» Expected
If an employee already has a saved draft for a specific template, that template must not appear in "Available Templates." Instead, the drafted version must be prominently surfaced under a "Continue Draft" or "In Progress" section. A template should only re-appear as available if the draft is discarded or the evaluation is fully completed.

2. 360° Evaluation Approval Flow
Context
When a branch employee (e.g., IT Helpdesk 1 from Agdangan branch) submits their self-evaluation, the form must travel through a structured chain of reviewers before it is considered final. Each reviewer along the chain has the authority to view and modify the employee's self-ratings before passing it further up.

Role Definitions
System Roles & Responsibilities

Employee
Any branch employee (e.g., IT Helpdesk 1, Agdangan). Submits the initial self-evaluation.
-Self-Eval Author-

Immediate Head
Branch Supervisor and/or Branch Manager — the employee's direct superior at the branch level.
-Branch Reviewer-

HR Supervisor
HR Supervisor at the HR Department. First HRD-level reviewer, finalizes and locks the evaluation.
-HRD First Review-

HR Manager
HR Manager at the HR Department. Conducts the final review and marks the evaluation as complete.
-HRD Final Approver-

Standard Flow — Employee Has an Immediate Head

Employee
Branch Staff · Self-Evaluation Author
- Completes and submits their self-evaluation using the assigned template.
- Once submitted, the employee can no longer edit their responses.

Immediate Head
Branch Supervisor / Branch Manager
- Receives the submitted self-evaluation for review.
- Can alter the employee's self-ratings before forwarding.
- Reviews and approves, then forwards the evaluation to the HR Supervisor.

HR Supervisor
HRD · First-Level Reviewer
- Receives the evaluation from the Immediate Head (or directly from the employee if no Immediate Head exists).
- Can alter the employee's self-ratings at this stage.
- Finalizes and locks the evaluation, preventing further rating changes.
- Forwards the locked evaluation to the HR Manager.

HR Manager
HRD · Final Approver
- Receives the finalized evaluation from the HR Supervisor.
- Can alter the employee's self-rating at this final stage.
- Reviews, accepts all changes, and marks the evaluation as Done / Completed.

Some branch doesn't have branch supervisor but they have branch Manager so the system must check it first whether the branch has branch supervisor or branch manager to forward the employee evaluation.

Alternate Flow — Employee Has No Immediate Head
If the employee does not have an assigned Immediate Head (e.g., a standalone branch employee with no branch supervisor or manager), the self-evaluation is submitted directly to the HR Department — skipping the branch-level review step entirely.
Employee  → HR Supervisor → HR Manager → Done ✓

3. Dedicated Review Pages for Immediate Heads
Requirement Overview
Users holding the Immediate Head role (Branch Supervisor or Branch Manager) must have a dedicated page within the Employee Portal where they can view and act on the self-evaluations of their direct subordinates. This page is entirely separate from the standard employee-facing evaluation interface.

Incoming Evaluation Queue
The page must display a list of all employee self-evaluations that have been submitted and are pending review by the Immediate Head. Each entry should show the employee's name, branch, template name, submission date, and current status.

Evaluation Viewer with Rating Edit Controls
When the Immediate Head opens a specific evaluation, they must be able to view the employee's full self-evaluation responses and have controls to adjust or override the employee's self-ratings directly within this view before forwarding it.

Forward / Submit Action
After reviewing and optionally modifying ratings, the Immediate Head must be able to submit the evaluation forward — sending it to the HR Supervisor. A confirmation step should be included to prevent accidental forwarding.

Review History / Audit Trail
The page should log what changes were made by the Immediate Head (if any), along with the timestamp of the review and forwarding action. This ensures full traceability across the entire approval chain.

Access Control Note
This review page must only be accessible to users with the Immediate Head role. Regular employees must not be able to access, view, or modify this interface. Role-based access must be enforced at both the UI and API level.
