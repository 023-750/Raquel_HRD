Employee List Pagination Performance Issue

A total of 2,000 employee records were inserted across all branches for testing.
When the Employee List page is opened for the first time, pagination is not being applied correctly. Instead of displaying only 10 employees per page, the system renders all 2,000 employee records at once.
This causes significant performance issues, including:
•	Slow page loading
•	UI lag and unresponsiveness
•	Excessive browser rendering

Interestingly, after the page finishes loading, pagination starts working normally and only shows the expected 10 employees per page but when it was refreshed the page loading starts once again.
Pagination Navigation Issue
The pagination navigation also becomes difficult to use when there are many pages. Currently, all page numbers are displayed at once (e.g., 1, 2, 3, 4, 5, 6, 7, 8, ... up to the last page), making the pagination bar excessively long and cluttered.

Expected Behavior
•	The Employee List should load only the required records for the current page (e.g., 10 employees per page) when the page is first opened.
•	Pagination should be applied before rendering the employee list.
•	The pagination navigation should display a limited number of page buttons, such as:

Previous | 1 | ... | 48 | 49 | 50 | 51 | 52 | ... | 200 | Next
•	The current page should remain visible along with nearby page numbers, while distant pages should be collapsed using ellipses (...).

Actual Behavior
•	All employee records are initially loaded and rendered before pagination is applied.
•	The page experiences noticeable lag when large datasets are present.
•	The pagination navigation displays too many page numbers, creating a cluttered user interface and reducing usability.

Impact
With large datasets (2,000+ employees), the Employee List page becomes slow, consumes unnecessary resources, and provides a poor user experience. The pagination navigation also becomes difficult to navigate due to the excessive number of page links displayed.

Self-Rating Approval Flow Issue
Test Scenario
Employee performed a self-rating:
Rank: Sales Associate I
Department: Acquired Properties
Branch: Raquel Pawnshop Main Office

After submitting the self-rating, the evaluation status was correctly set to:
Pending Dept Supervisor

Current Behavior
AP Supervisor I · Acquired Properties · Raquel Pawnshop Main Office
•	Receives the employee's evaluation request, which is correct.
•	However, the evaluation is not accessible through the Confirm Self-Rating.
•	A notification indicator appears, but clicking the approval/request area shows no pending evaluations.
•	The evaluation can only be accessed through the notification panel.
•	Once accessed from notifications, the approval process works correctly and the entire evaluation flow proceeds successfully until completion.
AP Supervisor II · Acquired Properties · Raquel Pawnshop Main Office
•	Receives no evaluation request.
•	Unable to view or act on the employee's submitted self-rating.
AP Supervisor III · Acquired Properties · Raquel Pawnshop Main Office
•	Receives no evaluation request.
•	Unable to view or act on the employee's submitted self-rating.

Expected Behavior
All supervisor-level positions within the employee's department should receive and be able to access evaluation requests according to the configured approval hierarchy.

Expected flow:
Branch Employee Self-Rating
→ Branch Supervisor
→ Branch Manager
→ HR Supervisor
→ HR Manager

This approval flow should be consistently applied to all branch employees and job titles.
Additional Issue
For AP Supervisor I, the request exists but is only visible through notifications. The same evaluation should also appear in the supervisor's pending evaluation/request list so it can be accessed without relying on notifications.

Exception
Employees under the Human Resource Department (HRD) should be excluded from this flow because they follow a separate evaluation workflow.
Impact
•	Some supervisors are unable to receive or access evaluation requests.
•	Approval routing is inconsistent across supervisor ranks.
•	Users may incorrectly assume that no pending evaluations exist.
•	The evaluation process becomes dependent on notifications rather than the designated approval screens.
•	This may cause delays or missed evaluations in production.
